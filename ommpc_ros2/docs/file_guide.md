# ommpc_ros2 — File Guide

What every file in this package does and how to use it. Organized by
directory. For the math/derivation behind the residual-learning pipeline see
[`residual_conventions.md`](residual_conventions.md); for the wind-generalization
experiment history see [`wind_generalization_experiment.md`](wind_generalization_experiment.md).

---

## Top level

| File | Purpose |
|---|---|
| `CMakeLists.txt` | Builds two executables (`ommpc_node`, `ecrl_data_collector_node`), the custom `PolyTraj`/`ReferenceState` messages, and (under `BUILD_TESTING`) the gtest suite plus two pure-math fixture generators. Depends on Eigen3, OSQP (found via `~/acados`'s CMAKE_PREFIX_PATH), and the standard ROS2/px4_msgs stack. |
| `package.xml` | ROS2 package manifest (`ament_cmake` build type). |
| `config/params.yaml` | Default `ommpc_node` parameters: takeoff height/speed, trajectory type, and the `MPC_params` block (Q/R weights, thrust/bodyrate limits, `step_T=0.05`s horizon discretization). Loaded by `launch/ommpc.launch.py`; individual fields can be overridden on the CLI with `-p key:=value` (see `collect_figure8_windy.py`'s pattern). |
| `launch/ommpc.launch.py` | Launches `ommpc_node` (with `config/params.yaml`) and `ecrl_data_collector_node` (default CSV `~/ecrl_datasets_v2/polynomial1.csv`) together. Run: `ros2 launch ommpc_ros2 ommpc.launch.py`. |

## `include/ommpc_ros2/` — core C++ headers

### `so3_math.h`
Minimal standalone SO(3) library: `hat`/`vee`, `exp` (Rodrigues), `log`
(clamped-`acos` to avoid NaN from floating-point trace drift past ±1 at
near-identity rotations — a real bug found and fixed this session), and
`leftJacobian`. No external deps beyond Eigen. This is the single source of
truth every other SO(3) usage in the repo (C++ and the Python/PyTorch ports)
must stay numerically consistent with.

### `nominal_dynamics.h`
The rigid-body one-step nominal dynamics map and the residual/error-state
algebra built on top of it — the "physics prior" the whole ECRL residual
pipeline is defined relative to:
- `nominalStep(x, u, dt)` — explicit-Euler `p_{k+1}=p_k+dt·v_k`,
  `v_{k+1}=v_k+dt(R_k e3·thracc - g·e3)`, `R_{k+1}=R_k·Exp(ω·dt)`.
- `boxminus(a, b)` — the §4 residual-target operator (world-frame, symmetric
  convention). This is what `d_k` is defined as.
- `controllerErrorState(x_ref, x_actual)` — the MPC's own §1 (asymmetric)
  error-state convention. **Not the same argument order as `boxminus`** —
  see the in-file comments if touching either.
- `composeFromResidual` / `residualToQpCorrection` — exact (non-linearized)
  machinery for folding a predicted 9-D residual `d` back into the QP's
  dynamics-equality constraint as an additive bias. Used by both the
  `enable_residual_correction` (NN) and `enable_integral_trim` (disturbance
  observer) paths in `ommpc_controller.hpp::execMPC`.

Must stay byte-for-byte in sync with `scripts/residuals.py` (checked by
`test/test_residuals_parity.py`) and, for the batched/differentiable
training-time port, with `scripts/knode_training/so3_torch.py` (checked by
`scripts/knode_training/test_so3_torch_parity.py`).

### `polynomial_trajectory.h`
Third-party (MIT-licensed, Zhepei Wang) piecewise-polynomial `Trajectory`/
`Piece` classes with pos/vel/acc/jerk/snap/crackle evaluation. Used for the
`trajectory="poly"` reference mode (trajectories streamed in over
`/drone_0_planning/trajectory` from `trajectory_generator.py`).

### `residual_model_ecrl.h`  *(generated — do not hand-edit)*
Header-only Eigen forward pass of the trained `ecrl` residual MLP
(`Linear(16,128)→tanh→Linear(128,128)→tanh→Linear(128,9)`, plus baked-in
input/output normalization), exposed as `ommpc::residual::ecrlForward(x)`.
Regenerated by `scripts/export_residual_weights.py` — see that entry below.
**Currently contains the rollout-trained (knode) model**, promoted this
session; the previous one-step-trained version is backed up at
`/tmp/residual_model_ecrl.h.onestep-backup` (not in the repo) and can be
regenerated from `models/ecrl_model.pt` any time (see Promotion note at the
bottom of this doc).

### `ommpc_controller.hpp`
The controller itself. Key pieces:
- `Odom_Data_t` / `Imu_Data_t` — PX4/ROS message → internal state adapters,
  handle the FRD/NED→FLU/ENU frame conversion (`R_mid`/`q_body` rotation)
  shared with `ecrl_data_collector_node.cpp`.
- `MpcWrapper` — raw OSQP problem assembly (sparse Hessian/constraint CSC
  construction, `applyResidualCorrection` for overwriting the dynamics-
  equality RHS with a residual bias, `solve()`).
- `Parameter_t` — all tunable params, including `enable_residual_correction`
  / `residual_clip_norm` (NN correction) and `enable_integral_trim` /
  `integral_trim_tau` (disturbance-observer trim).
- `MpcController::execMPC` — the per-cycle entry point:
  1. builds the QP's initial error state from the current odometry,
  2. runs the disturbance-observer bookkeeping unconditionally (cheap: one
     `nominalStep` + `boxminus`, leaky-integrated with time constant
     `integral_trim_tau`) so toggling the trim mid-flight never starts cold,
  3. if either correction flag is on, builds `d_total` (ecrl NN prediction +
     trim `d_hat_`), clips it to `residual_clip_norm`, and injects it via
     `residualToQpCorrection` + `applyResidualCorrection`,
  4. solves the QP, extracts the first-step control, updates the RLS
     `thr2acc` thrust-mapping estimator.
- `setHoverReference` / `setTextReference` / `setTrajectoryReference` —
  build the reference trajectory over the horizon for hover, text-file, and
  polynomial-trajectory modes respectively (`ommpc_node.cpp` builds the
  figure-8/circle references itself, then calls `setTextReference`).

## `src/` — nodes

### `ommpc_node.cpp`
Main control-loop node, 100 Hz timer. FSM:
`WAIT_OFFBOARD → ARMED_WAIT → TAKEOFF → HOVER → TRACKING → LAND`.
`trajectory` param selects the TRACKING reference source: `"hover"`
(stays in HOVER), `"figure8"` / `"circle"` (built-in analytic references,
hardcoded 20 s period), `"text"` (reads `ref_txt.ref_filename` from package
share), or `"poly"` (consumes `PolyTraj` messages from
`trajectory_generator.py` via `/drone_0_planning/trajectory`). Publishes
`/fmu/in/vehicle_rates_setpoint` (body-rate + thrust control to PX4) and
`/ommpc/current_reference` (`ReferenceState` — the resolved reference/
setpoint/fsm-state/OSQP-status this cycle, consumed by the data collector).
Declares and wires every `Parameter_t` field as a ROS2 parameter, including
`enable_residual_correction`/`residual_clip_norm` and
`enable_integral_trim`/`integral_trim_tau` (both default off, log an
`RCLCPP_WARN` when enabled since they affect flight behavior).

Run directly: `ros2 run ommpc_ros2 ommpc_node --ros-args --params-file config/params.yaml -p trajectory:=figure8`

### `ecrl_data_collector_node.cpp`
Raw-only data logger — deliberately contains **no** residual computation
(that all lives in `scripts/residuals.py`, offline). Subscribes to odometry,
the applied rates setpoint, vehicle status, and `/ommpc/current_reference`;
pairs consecutive odometry ticks into one CSV row per transition
(`x_k → x_{k+1}`, with the control/reference/fsm/OSQP-status that were in
effect at tick `k`). Writes `schema_version=3` CSVs (see header comment for
the exact column layout) to `csv_filepath` (a runtime-settable parameter
— `collect_figure8_windy.py` changes it per-run without restarting the
node). Only logs while armed + OFFBOARD; resets pairing (`has_prev_=false`)
on any gap.

v3 adds three trailing diagnostic columns beyond v2's raw
state/control/reference layout: `trim_norm_k` (the disturbance-observer's
`d_hat_` norm, tracked unconditionally regardless of
`enable_integral_trim`), `ecrl_norm_k` (the raw ecrl NN prediction norm,
pre-clip, 0 when `enable_residual_correction` is off), and
`correction_clipped_k` (1 if the combined ecrl+trim correction hit
`residual_clip_norm` that cycle). Sourced from new
`MpcController::last_trim_norm`/`last_ecrl_norm`/`last_correction_clipped`
members (populated in `execMPC`) via new `ReferenceState.msg` fields.
`residuals.py::load_raw_csv` accepts both v2 and v3 (the new columns are
additive — nothing in the offline pipeline reads them yet), so existing v2
training pools remain valid; use them to check whether a correction was
clipping away most of its effect on a given flight.

Run directly: `ros2 run ommpc_ros2 ecrl_data_collector_node --ros-args -p csv_filepath:=/path/to/out.csv`

## `msg/`

- `PolyTraj.msg` — one polynomial-trajectory piece-set (coefficients +
  durations + start time), published by `trajectory_generator.py`, consumed
  by `ommpc_node`'s `trajCallback`.
- `ReferenceState.msg` — the resolved reference/setpoint/`thr2acc`/FSM-state/
  OSQP-status published every cycle by `ommpc_node`, consumed by
  `ecrl_data_collector_node`.

## `scripts/` — offline residual pipeline, data collection, evaluation

### `residuals.py`  *(the single source of truth for every residual definition)*
Pure NumPy/pandas module — no torch dependency. Mirrors
`nominal_dynamics.h` exactly (`so3_exp`/`so3_log`/`nominal_step`/`boxminus`/
`controller_error_state`, kept in parity by `test/test_residuals_parity.py`).
Public API:
- `load_raw_csv(path)` — validates the `# ecrl_schema_version=2` header,
  coerces/drops any stray repeated header rows (from a mid-collection
  restart), tags rows with `_source_file`.
- `compute_targets(df)` — computes `d_0..d_8` (`d_k = boxminus(x_{k+1}^meas,
  nominal_step(x_k^meas, u_k^applied, dt))`) and a `target_valid` mask
  (rejects clock/timestamp mismatches and dropout gaps).
- `ambient_features(df)` — 8-D body-frame velocity/rate/thrust features, no
  reference trajectory.
- `ecrl_features_and_target(df)` — 16-D error-state features (`dx` controller
  error state, `du` control error, `r_ref` = `Log(R_ref_k)`) regressed onto
  the same world-frame `d_k` target as `ambient`.
- `linearized_residual_diagnostic(df)` — reconstructs the old (pre-refactor)
  linearized residual `d_lin` for comparison, plus `plot_truncation_diagnostic`
  to visualize the truncation term `d_k - d_lin` vs. error magnitude.

CLI: `python3 scripts/residuals.py <csv_path> [--diagnostic-plot out.png]`

### `train_residuals_v2.py`  *(current production trainer — one-step regression)*
CLI entry point / orchestrator only — argparse plus the STEP 1-7 pipeline
wiring. Implementation is split across three files (below) so loading,
model/training, and evaluation/export can be read and reused independently:
diversity-aware loading (calm + windy CSV pools, near-zero residual
filtering, quantile-stratified spatial binning so no single operating regime
dominates), a `spectral_norm`-regularized MLP (`ResidualMLP`, default hidden
`[128,128]`, tanh) trained with AdamW + OneCycleLR + early stopping +
gradient clipping, then exports `{adapter}_model.pt` /
`{adapter}_model_normalized.pt` (TorchScript, the latter self-normalizing) +
`.onnx` + `{adapter}_metadata.json` + a training-curves PNG into
`--output_dir` (default `models/`). Also re-exports `ResidualMLP` /
`NormalizedResidualMLP` / `load_csv_files` at module level so
`scripts/knode_training/train_knode.py` and
`scripts/sample_efficiency_sweep.py`'s `from train_residuals_v2 import ...`
keep working unmodified.

```
conda run -n ecrl python3 scripts/train_residuals_v2.py \
    --adapter ecrl --calm_dir ~/ecrl_datasets_v2 --windy_dir ~/ecrl_datasets_v2/windy \
    --calm_files 30 --windy_files 40 --output_dir models/
```
Key knobs: `--adapter {ecrl,ambient}`, `--target_samples`,
`--residual_filter_pct`, `--n_bins`, `--epochs`, `--hidden_dims`.

### `residual_data.py`
Data loading, diversity-aware sample selection, and normalization/splitting,
split out of `train_residuals_v2.py`: `load_csv_files()` (residuals.py-backed
CSV loading for either adapter), `filter_trivial_residuals()`,
`stratified_bin_sampling()`, `ResidualDataset` (thin `torch.utils.data.Dataset`
wrapper), `normalize()`, and `split_train_val_test()` (70/15/15 shuffled
split). `load_csv_files` is imported directly by `train_knode.py` and
`sample_efficiency_sweep.py` (via `train_residuals_v2.py`'s re-export).

### `residual_model.py`
Model architecture and training loop, split out of `train_residuals_v2.py`:
`ResidualMLP` / `NormalizedResidualMLP` (unchanged signatures — imported
directly by `train_knode.py` and `sample_efficiency_sweep.py` via
`train_residuals_v2.py`'s re-export) and `train_model()` (AdamW + OneCycleLR +
gradient clipping + early stopping, saves the best-val-loss checkpoint each
time it improves).

### `residual_evaluate.py`
Test-set evaluation, metadata, and export, split out of
`train_residuals_v2.py`: `evaluate_test_set()` (per-coordinate physical-unit
RMSE), `save_metadata()`, `export_models()` (removes spectral-norm hooks,
exports ONNX + TorchScript, raw and self-normalizing), and
`plot_training_curves()`.

### `train_residuals.py`
Earlier/superseded version of the trainer (pre-`residuals.py` refactor,
reads baked-in `dx_*`/`du_*`/`res_*`/`r_ref_*` columns directly from CSVs
rather than computing them from raw logs). Kept for history; **not** the
one to use — use `train_residuals_v2.py` (or `knode_training/train_knode.py`
for rollout training).

### `evaluate_model.py`
Scores a trained normalized model against a **directory** of held-out
`polynomial*.csv` files, vs. a zero-residual baseline, printing per-axis and
overall RMS reduction.
```
conda run -n ecrl python3 scripts/evaluate_model.py \
    --model models/ecrl_model_normalized.pt --adapter ecrl --data_dir /path/to/held_out
```

### `evaluate_figure8_windy.py`
Same methodology as `evaluate_model.py` but scores **both** `ecrl` and
`ambient` models side by side against a **single** collected CSV (meant for
the figure-8-in-wind eval flights), printing a comparison table.
```
conda run -n ecrl python3 scripts/evaluate_figure8_windy.py \
    --csv ~/ecrl_datasets_v2_eval_windy/figure8/figure8_windy_run1.csv \
    --ecrl_model models/ecrl_model_normalized.pt --ambient_model models/ambient_model_normalized.pt
```

### `plot_figure8_windy.py`
Visualizes one collected figure-8-in-wind flight (TRACKING rows only):
6-panel figure — XY reference-vs-actual path, x/y vs. time, altitude vs.
time, XY tracking-error-norm vs. time, true residual norm `|d_k|` vs. time,
and remaining-error-after-correction (baseline vs. ecrl vs. ambient,
smoothed). Prints mean XY tracking error and mean remaining-error
percentages to stdout.
```
conda run -n ecrl python3 scripts/plot_figure8_windy.py --csv <path.csv> [--out <path.png>]
```

### `collect_figure8_windy.py`  *(SITL closed-loop data-collection orchestrator)*
Owns an entire live PX4 SITL + Gazebo session end-to-end: starts
MicroXRCEAgent, PX4 SITL (`ecrl_windy_eval` world, headless), injects live
wind via `gz topic`, launches `ommpc_node` (forcing `trajectory:=figure8`
and optionally the residual-correction/integral-trim params via CLI `-p`
overrides — these are read once at node startup, not settable afterward)
and `ecrl_data_collector_node` pointed at a fresh CSV path, waits for
HOVER→TRACKING, records `--periods × --period_s` seconds, then tears
everything down via a retry-and-verify SIGKILL-to-process-group loop (plain
SIGTERM/pkill was found unreliable — see module docstring for the full
rationale, including a PX4 pxh>-console stdin/runaway-log-write hazard this
script works around).
```
python3 scripts/collect_figure8_windy.py \
    --csv_path ~/ecrl_datasets_v2_eval_windy/figure8/run1.csv \
    --wind_x 1.3 --wind_y 0.7 --periods 6 \
    [--enable_residual_correction] [--residual_clip_norm 0.08] \
    [--enable_integral_trim] [--integral_trim_tau 10.0]
```

### `export_residual_weights.py`  *(code generator — do not hand-edit its output)*
Reads a plain (non-normalizing) TorchScript model + matching metadata JSON
and emits `include/ommpc_ros2/residual_model_ecrl.h`: flat static Eigen
weight/bias arrays plus the `ecrlForward()` forward pass (input
normalize → 2×(Linear+tanh) → Linear → output de-normalize). No
libtorch/onnxruntime dependency introduced — only Eigen.
```
conda run -n ecrl python3 scripts/export_residual_weights.py \
    [--model_path models/ecrl_model.pt] [--metadata_path models/ecrl_metadata.json] \
    [--out_header include/ommpc_ros2/residual_model_ecrl.h]
```
Regenerate whenever a new model is promoted to production (see
`--model_path`/`--metadata_path` to point at e.g.
`scripts/knode_training/output/ecrl_knode_model.pt` +
`ecrl_knode_metadata.json` instead of the defaults).

### `sample_efficiency_sweep.py`
Standalone sweep: trains fresh `ecrl` and `ambient` models at
`N ∈ {100,...,20000}` training samples (5 trials each) on
`~/ecrl_datasets/windy` (note: **old**, pre-refactor dataset layout with
baked-in `dx_*`/`res_*` columns — not `~/ecrl_datasets_v2`), reporting 3D
position RMSE vs. N to show ecrl's sample-efficiency advantage over
ambient. Saves `models/sample_efficiency_results.json` and `.png`.
Currently stale relative to the v2 pipeline (flagged as such in the paper
draft's Sample Efficiency Sweep subsection — would need porting to
`residuals.py`/`ecrl_datasets_v2` before reuse).

### `trajectory_generator.py`
ROS2 node: publishes randomized polynomial trajectories
(`PolyTraj` messages) on `/drone_0_planning/trajectory` for the
`trajectory="poly"` data-collection mode — the source of the
`polynomial*.csv` training pool. Params: `num_trajectories`,
`traj_duration_min/max`, `hover_height`, `xy_range`, `z_min/max`,
`delay_between_trajectories`, `windy` (writes to a `windy/` subdirectory of
`save_file`'s directory when set).

## `scripts/knode_training/` — KNODE-MPC-style multi-step rollout training

A self-contained, separate pipeline (does not touch `train_residuals_v2.py`
or the production `models/` directory as a side effect). Where the v2
trainer scores each row in isolation against its own precomputed `d_k`
target, this rolls the **combined physics+NN model** forward over a window
of real logged data and backprops through the composed trajectory —
targeting the fact that the live controller composes the model's own errors
with itself across a 20-step MPC horizon, which one-step regression never
scores.

### `so3_torch.py`
Batched, autodiff-safe PyTorch port of `residuals.py`'s SO(3) math
(`so3_exp`, `so3_log`, `quat_to_rot`, `rot_to_quat`, `hat`, `nominal_step`,
`boxminus`, `controller_error_state`, `compose_from_residual`). Small-angle
branches use `torch.where` with both branches computed unconditionally (not
Python `if`/indexing) so a NaN gradient from the untaken branch at
`theta≈0` can't contaminate the whole batch's backward pass. `so3_log`'s
`acos` clamp is `[-1+1e-7, 1-1e-7]` (strictly inside, not `[-1,1]`) — an
autodiff-specific fix distinct from the C++/NumPy versions' clamp, needed
because `0 * inf = NaN` at exactly ±1 poisons gradients even under
`torch.where` masking.

### `test_so3_torch_parity.py`
Parity check: `so3_torch.py` vs. `residuals.py` on random batched inputs
(including small-angle cases), plus a gradient-finiteness check at
`theta≈0` (the actual failure mode that matters more than a value
mismatch). Run: `conda run -n ecrl python3 scripts/knode_training/test_so3_torch_parity.py`

### `windows.py`
`build_rollout_windows(df, rollout_steps, stride)` — groups rows by
`_source_file`, finds maximal contiguous runs (same contiguity check as
`residuals.py::linearized_residual_diagnostic`: row i's `k+1` tick must
equal row i+1's `k` tick), slices fixed-length rollout windows, drops any
window touching an invalid row. `RolloutWindowDataset` wraps the result for
`DataLoader`.

### `train_knode.py`  *(main rollout trainer)*
For a window of length `W` starting at the row's own measured `x_0`:
composes `nominalStep` + the model's own prediction each step
(`x_hat_{t+1} = compose_from_residual(nominal_step(x_hat_t, u_applied_t),
model(feat(x_hat_t, ...)))`, features built from the model's **own
rolled-out state**, not the logged one, from step 2 onward), scores against
the real measured trajectory. Reuses `ResidualMLP`/`NormalizedResidualMLP`
and `load_csv_files` (for norm stats) from `../train_residuals_v2.py`
unmodified, so output is drop-in compatible with
`export_residual_weights.py`.
```
conda run -n ecrl python3 scripts/knode_training/train_knode.py \
    --calm_files 19 --windy_files 14 --rollout_steps 10 --batch_size 64 \
    --output_dir scripts/knode_training/output/
```
Key knobs beyond `train_residuals_v2.py`'s: `--rollout_steps` (default 10),
`--stride` (default `rollout_steps // 2`), `--one_step_weight` (default 0.0
— blend toward one-step loss for ablation), `--loss_weights` (9 floats,
per-block p/v/theta weighting).

### `evaluate_knode_rollout.py`
The actual proof-of-value check: rolls out **both** the knode-trained model
and the production one-step-trained model recursively over the same
held-out windows (default: this session's genuinely-held-out
`~/ecrl_datasets_v2_eval_windy/figure8/figure8_windy_run1.csv`, TRACKING
rows only), plus a zero-correction physics-only reference, and plots RMSE
**as a function of rollout step** — the figure that shows whether errors
compound more slowly, which a single aggregate RMSE would hide.
```
conda run -n ecrl python3 scripts/knode_training/evaluate_knode_rollout.py \
    [--rollout_steps 20] [--stride 5] [--adapter ecrl] \
    [--knode_model .../output/ecrl_knode_model_normalized.pt] \
    [--baseline_model ../../models/ecrl_model_normalized.pt]
```

### `output/`
Training artifacts from the run used this session (`--calm_files 19

| `test_residual_mlp_parity.py` | Cross-language check: the hand-ported `ecrlForward()` vs. the source `*_normalized.pt` model, tolerance `2e-4`. `--model_path` selects which normalized model to check against (must match whatever the fixture header was generated from). `conda run -n ecrl python3 test/test_residual_mlp_parity.py test/fixtures/residual_mlp_fixture.csv [--model_path models/ecrl_model_normalized.pt]` |
| `fixtures/residual_mlp_fixture.csv` | Generated fixture consumed by `test_residual_mlp_parity.py` — regenerate after any `residual_model_ecrl.h` regen. |

## Typical end-to-end workflows

**Fly with a given controller configuration (SITL):**
```
colcon build --packages-select ommpc_ros2 && source install/setup.bash
ros2 launch ommpc_ros2 ommpc.launch.py
# or, for the windy figure-8 eval harness specifically:
python3 scripts/collect_figure8_windy.py --csv_path <out.csv> --enable_residual_correction --enable_integral_trim
```

**Retrain and promote a new residual model:**
```
conda run -n ecrl python3 scripts/train_residuals_v2.py --adapter ecrl ...      # or knode_training/train_knode.py
conda run -n ecrl python3 scripts/export_residual_weights.py --model_path <new.pt> --metadata_path <new_metadata.json>
colcon build --packages-select ommpc_ros2
build/ommpc_ros2/gen_residual_mlp_fixture test/fixtures/residual_mlp_fixture.csv
conda run -n ecrl python3 test/test_residual_mlp_parity.py test/fixtures/residual_mlp_fixture.csv --model_path <new_normalized.pt>
build/ommpc_ros2/test_nominal_dynamics   # sanity: unrelated to the model, but cheap to rerun
```

**Verify the C++/Python physics stay in sync after touching `nominal_dynamics.h` or `so3_math.h`:**
```
colcon build --packages-select ommpc_ros2
build/ommpc_ros2/gen_nominal_dynamics_fixture test/fixtures/nominal_dynamics_fixture.csv
conda run -n ecrl python3 test/test_residuals_parity.py test/fixtures/nominal_dynamics_fixture.csv
```
